# Audit de sécurité : Atelier du Logo par John Apple

- **Dépôt** : `johnapplewan/atelier-du-logo`, branche `claude/import-atelier`, commit `c66e0ba` (arbre propre).
- **Date** : 9 novembre 2026.
- **Profil** : *quick*. C'est une revue du code source par une seule personne, avec des preuves en local (données factices, réseau coupé, aucun site ni API réels testés).
- **Couverture** : partielle (voir la dernière section). C'est le premier audit, il n'y en a pas d'antérieur.

## État : corrigé

Les trois constats sont corrigés. Le code d'avant correction, celui audité ci-dessous, correspond au commit `c66e0ba`.

- **Vérification** : les preuves de l'audit ont été relancées sur la version corrigée.
  - `poc.js` répond `{"thumbnail_xss_read_key":null,"history_id_xss":null,"live_family_attr_injection":[false,null,null]}`.
  - `poc2.js` répond `{"font_glyph_xss":null}`.
  - Le serveur local répond 403 à un `Host` forgé et à une requête sans jeton.
- **Tests de non-régression** : `tests/security.js` (F1, F2) et `tests/mcpb.js` (F3), lancés par `npm test`.

### Correctifs appliqués
- **F1** :
  - à l'import, la vignette est redessinée à partir du dessin validé (`importThumb`) ; celle du fichier est ignorée ;
  - toute vignette est affichée en `<img src="data:image/svg+xml,…">` (`thumbImg`), où aucun script ne peut s'exécuter. Cela protège aussi les vignettes déjà stockées.
- **F2** :
  - **Historique** : les identifiants sont limités à `[\w-]{1,40}` et les libellés à 200 caractères (`validHist`). Les identifiants sont aussi échappés à l'affichage. Un historique non conforme est retiré à l'import, et le dessin est conservé.
  - **Texte « live »** : la police n'accepte que lettres, chiffres, espaces et `. , & ( ) _ + -` (`LIVE_FAMILY`). La langue, le sens et la graisse sont contrôlés, et chaque valeur est échappée dans `liveAttrs`.
  - **Polices** : chaque glyphe ne contient que des commandes et des nombres (`GLYPH_D`). Chasses, crénage et métriques sont des nombres, et `gkey` est contrôlé (`validCustom`). Une police non conforme est refusée à l'import comme au chargement.
- **F3** :
  - un jeton aléatoire est créé à chaque lancement et injecté seulement dans la page servie ; il est exigé sur tout `/bridge/` ;
  - l'en-tête `Host` doit être `127.0.0.1:<port>` ou `localhost:<port>` ;
  - le confinement des fichiers compare désormais avec `APP + path.sep`.

## Synthèse (constats initiaux)

| # | Gravité | Constat |
|---|---|---|
| F1 | **Élevée** | Un fichier de projet `.atelier.json` piégé exécute du code dès l'import, par sa vignette, et peut lire la clé API Anthropic. |
| F2 | **Élevée** | Le même fichier peut injecter du code par trois autres champs : identifiant d'historique, police d'un texte « live », données de glyphes d'une police importée. |
| F3 | Faible | Le serveur local de l'extension Claude Desktop ne vérifie pas l'en-tête `Host`, et n'importe quel client sans `Origin` peut s'abonner au pont. |

**La cause commune de F1 et F2** : l'import de projets fait confiance à des chaînes de présentation venues du fichier, puis les insère telles quelles dans le HTML ou dans des attributs SVG. L'import entre appareils est une fonction prévue. Recevoir un fichier de projet d'une autre personne (client, collègue, modèle partagé) est donc un usage réaliste, et c'est là qu'est la frontière de confiance.

## F1 · Vignette de projet insérée telle quelle (code exécuté à l'import)

- **Qui attaque** : l'auteur d'un fichier `.atelier.json` que l'utilisateur importe (« Projets » › « Ouvrir un fichier… »).
- **Chemin dans le code** :
  - `src/template.html`, `importFile()` : `thumb: typeof p.thumb==="string" ? p.thumb : ""`, sans aucune autre validation.
  - Le projet est enregistré dans IndexedDB.
  - `renderProjects()` l'affiche ensuite par `innerHTML` : `` `<button class="pthumb" …>${p.thumb||…}</button>` ``.
- **Résultat observé en local** : avec une vignette `<img src=x onerror=…>`, le code s'exécute dans la page de l'atelier dès l'affichage de la liste des projets, c'est-à-dire juste après l'import. Il lit `localStorage["atelier-logo-api-key"]` et renvoie la clé factice `sk-ant-DUMMY-…`.
- **Impact** :
  - Sur le site GitHub Pages ou dans l'appli installée, il n'y a pas de politique CSP. Le script peut envoyer la clé API à un tiers, qui consommera du crédit payant.
  - Il peut aussi lire ou modifier tous les projets de l'appareil.
  - Le code reste stocké : il se relance à chaque ouverture de « Projets ».
  - Dans l'artifact, la CSP de claude.ai bloque l'envoi de données vers l'extérieur, mais le script garde la main sur la page.
- **Correctif minimal** : ne jamais accepter de vignette importée.
  - À l'import, remplacer `thumb` par `thumbSVG(p.doc.layers)` recalculé (fonction existante), ou par `""`.
  - Dans `renderProjects()`, n'afficher que des vignettes produites par l'atelier : par exemple, régénérer la vignette si elle ne vient pas de `thumbSVG`, ou la mettre dans un `<img src="data:image/svg+xml,…">`, où les scripts ne s'exécutent pas.
- **Test de non-régression** : importer un projet dont `thumb` contient `<img onerror>` ; vérifier que rien ne s'exécute et que la vignette affichée est recalculée.

## F2 · Trois autres champs du fichier injectés dans des attributs

Même attaquant, même fichier, même impact que F1. Il faut en plus un geste de l'utilisateur : ouvrir le projet, puis l'historique, la police, ou survoler le texte.

1. **Identifiant d'historique.**
   - `validHist()` vérifie seulement que `e.id` est une chaîne.
   - `renderHistory()` l'insère sans échappement : `data-h="${e.id}"` et `data-hc="${e.id}"`.
   - **Observé** : un id `h"><img onerror=…>` exécute du code quand on ouvre l'historique.
2. **Texte « live ».**
   - `validLayers()` accepte `live.family` (toute chaîne de 60 caractères au plus) et ne contrôle ni `live.lang`, ni `live.dir`, ni `live.weight`.
   - `liveAttrs()` retire seulement l'apostrophe : `font-family="'${family}'…"`, `xml:lang="${lang}"`, `direction="${dir}"`.
   - **Observé** : `family = 'Inter" onmouseover="…" x="'` place un gestionnaire `onmouseover` sur le `<text>` du dessin, et le code s'exécute au survol.
3. **Glyphes d'une police importée** (la clé `fonts` du fichier).
   - `validCustom()` ne vérifie ni le contenu de `G.gl`, ni `G.adv`, ni `G.m`.
   - La grille de « Mes polices » les insère dans `d="${d}"` et dans `viewBox`.
   - **Observé** : un glyphe `M0 0"/></svg><img onerror=…>` exécute du code quand on ouvre la police.

**Correctif minimal** : valider à l'entrée, au même endroit que le reste.

- **Historique** : `validHist` exige `/^[\w-]{1,40}$/` pour `e.id`. Échapper aussi `e.id` dans `renderHistory`.
- **Texte « live »** : `validLayers` limite les valeurs.
  - `live.family` : `/^[\w À-ÿ.-]{1,60}$/`.
  - `live.lang` : `/^[a-z]{2,3}(-[A-Za-z0-9]{2,8})?$/` ou vide.
  - `live.dir` : `auto`, `ltr` ou `rtl`.
  - `live.weight` : entier entre 100 et 900.
  - `liveAttrs` applique en plus `esc()` à chaque valeur.
- **Polices** : `validCustom` vérifie que :
  - chaque `G.gl[c]` correspond à `/^[MLQCZ0-9eE.\s+-]*$/i` ;
  - chaque `G.adv[c]` est un nombre fini ;
  - `G.m.asc` et `G.m.desc` sont des nombres finis ;
  - `gkey` correspond à `/^custom-[\w-]+$/`.

  Tout ce qui ne passe pas est rejeté à l'import.

**Test de non-régression** : les trois fichiers de la preuve ci-dessous doivent être refusés, ou affichés sans exécution.

## F3 · Pont local de l'extension : pas de contrôle de `Host`, abonnement sans authentification

- **Chemin dans le code** :
  - `tools/mcpb/server.js` refuse les requêtes dont l'en-tête `Origin` est étranger, ce qui fonctionne (403 constaté).
  - En revanche, il ne vérifie pas `Host`, et accepte `GET /bridge/events` sans `Origin`.
  - `ask()` envoie chaque commande de Claude au **dernier** client abonné.
- **Observé en local** : `GET /bridge/events` avec `Host: evil.example:47611` et sans `Origin` répond `200 text/event-stream`.
- **Impact** : une page web qui réussit un *DNS rebinding* vers 127.0.0.1, ou toute requête sans `Origin` (navigation, balise `<img>`), peut devenir l'abonné actif. Elle peut alors :
  - **bloquer le pont** : les outils de Claude n'obtiennent plus de réponse et finissent en délai dépassé ;
  - **recevoir le contenu des commandes** : les modifications envoyées par `atelier_appliquer` et les réponses aux bulles.

  En revanche, elle ne peut pas répondre à la place de l'atelier : le POST de résultat, qui porte un `Origin`, est refusé. La gravité est faible.
- **Correctif minimal** :
  - **Jeton de lancement** : le serveur génère un jeton aléatoire au démarrage, l'injecte dans la page qu'il sert (même mécanisme que le marqueur `/*__ATELIER_BRIDGE__*/`), et exige ce jeton sur `/bridge/events` et `/bridge/result`.
  - **Contrôle de `Host`** : refuser toute requête dont `Host` n'est pas `127.0.0.1:<port>` ou `localhost:<port>`.
- **À valider** : que des navigateurs récents laissent encore une page publique joindre 127.0.0.1 par rebinding ou par `<img>`. La protection *Private Network Access* de Chrome peut le bloquer. Le correctif reste utile dans tous les cas.

## Points vérifiés sans problème

- **Réponses de Claude** (copier-coller, clé API, extension, `atelier/patch`) : les tracés sont relus en nombres seulement (`parsePathD`), les couleurs validées en `#RRGGBB`, les noms tronqués. Les noms de calques et les textes des bulles sont échappés partout où ils sont affichés. Les calques verrouillés ne sont pas modifiés.
- **Serveur de l'extension** :
  - Il écoute uniquement sur 127.0.0.1.
  - Le chemin de fichier est normalisé et confiné au dossier `app/`. La comparaison `startsWith(APP)` n'ajoute pas de séparateur, mais aucun dossier voisin ne commence par `app` : c'est sans effet aujourd'hui, et il vaut mieux comparer avec `APP + path.sep`.
  - Le corps des requêtes est limité à 20 Mo.
  - L'ouverture du navigateur n'utilise qu'une URL fixe.
- **Secret Wero** : il est lu seulement lors d'un *push* sur `main` (jamais sur une pull request venant d'un fork), et n'est jamais écrit dans le dépôt. Il est seulement encodé dans la page publiée : c'est voulu et documenté, ce n'est pas un chiffrement.
- **Workflow Pages** : permissions minimales (`contents: read`, `pages: write`, `id-token: write`).
- **Service worker** : il ne met en cache que des requêtes GET de la même origine, ni `/bridge/` ni `/downloads/`, et il n'est jamais actif dans l'artifact.
- **Fenêtres détachées** : même origine. Le titre et l'URL sont échappés.
- **Clé API** : elle est stockée en clair dans le navigateur, ce qui est le choix documenté. Elle n'est envoyée qu'à `api.anthropic.com` par le SDK officiel. Elle ne devient exposée que par une injection de code (F1, F2), d'où leur gravité.

## Couverture et limites

- **Revu** :
  - les points d'entrée de données externes de `src/template.html` : import de projets, polices et images, réponses de Claude, base de l'artifact, ponts ;
  - `src/sw.js` ;
  - `tools/mcpb/server.js` ;
  - `build.js` ;
  - `.github/workflows/pages.yml`.
- **Non revu en profondeur** :
  - l'import d'image et sa vectorisation (données de pixels, faible risque) ;
  - l'import TTF/OTF par opentype.js (bibliothèque tierce) ;
  - le contenu des réponses de l'API au-delà du JSON appliqué ;
  - le comportement réel de Claude Desktop et des navigateurs face au rebinding.
- **Pas de garantie d'exhaustivité.** Un audit au profil *standard* (plusieurs passes indépendantes) reste recommandé après les correctifs.
